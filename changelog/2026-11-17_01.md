## Why Care?

Some of our sites are written in MDX: markdown with components dropped into the
prose, like a bar chart between two paragraphs. Those sites rendered MDX with
Astro's own pipeline, so they got none of LFM (shared heading anchors,
citations, callouts) and kept a second render path alive. Now an `.mdx` file goes
through LFM like any other markdown, and its components come along.

## What's New?

- **MDX is a trigger syntax.** With `mdx` on, `<BarChart caption="…" items={[…]} />`
  becomes a component node, the same shape a `:::callout` produces.
- **No component lookup.** Other triggers name a component the site finds in its
  own map. An MDX file already imports its components, so the node records that
  import: `src/components/BarChart.astro`. The site renders that Astro component
  with the props.
- **Nothing runs.** Props are read as data (strings, numbers, arrays, objects).
  One that needs real code is listed in `dynamicProps` with a warning instead.
- **`re:Invent` stays a word.** LFM had been reading `:Invent` as an inline
  directive, and sites printed nothing for it. "AWS bills re as the largest…" was
  live on cathode.co.

## How It Was Checked

All 300 tests pass, including new ones for MDX and for word colons. edviro-blog's
13 MDX articles render through it with every chart and stat block byte-identical
to their Astro MDX output, the same text and tag structure, and all 80 heading
anchors unchanged.

Turn it on for `.mdx` files only: MDX changes how `<` and `{` parse. See
[MDX](https://github.com/lossless-group/lossless-flavored-markdown-package/blob/master/docs-v/mdx.md).
