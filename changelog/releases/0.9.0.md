## Why Care?

In Obsidian you write something once and show it wherever it's relevant:
`![[Google Maps#Google Maps API managing policies.]]` puts that section of the
Google Maps note into the note you're writing. On the web, that line used to
come out as literal text. Now the section shows up in place, so a vault's
cross-references survive publishing.

## What's New?

- **`crossReferenceEmbeds` option.** Give it a `load` function that returns the
  markdown of a named document (LFM never reads files itself), and every
  `![[…]]` on its own line becomes a `cross-reference-embed` block holding that
  section.
- **A section is what Obsidian means by one:** its heading down to the next
  heading at the same level, subsections included. `#A#B` reaches into a
  section; `![[Note]]` takes the whole document. Headings match ignoring case
  and markup, or by slug.
- **Both label orders work:** Obsidian's `![[Note#Heading|Label]]` and
  `![[Note|Label#Heading]]`.
- **It knows where it came from.** Each block carries the source's title and
  link, so a renderer can say "From *Google Maps*" and link to the original.
- **Missing targets don't vanish.** A block whose document or section can't be
  found still arrives, empty, with `status` saying why, and `onUnresolved`
  reports it.
- **A reference renderer** for Astro sites: `CrossReferenceContentEmbed.astro`
  in astro-knots' `packages/lfm-astro`, which reads as part of the page with a
  thin rule, a source line and an "Open original" link.

## How It Was Checked

All 310 tests pass, ten of them new: sections and subsections, both label
orders, slug and case matching, whole documents, missing documents and
sections, file embeds left alone, a self-embedding note stopping at
`maxDepth`, and embedded headings getting ids on the host page. The reference
component was rendered in a scratch Astro page to check that it reads as part
of the prose.

## Under the Hood

- Named "cross-reference" embeds rather than plain embeds, so they don't
  collide with link previews, media embeds or anything else called an embed.
- Embedded documents are parsed with the host's own options, one level deeper,
  so their callouts, wikilinks and nested embeds work. Heading ids, eyebrows and
  citations are left to the host, which computes them once for the whole page.
- Runs before callouts, citations, heading ids and wikilinks. Embedded headings
  get ids on the host page and are marked `inContainer: 'cross-reference-embed'`,
  so a table of contents can list them or leave them out.
- Parsing becomes async when the option is on; `parseMarkdown` already is.
- Not yet: Obsidian block references (`![[Note#^block-id]]`), and renumbering
  footnotes from an embedded section into the host's citations.
- Named `lfmCrossReferenceEmbeds`: no formal remark plugin handles Obsidian
  section embeds, which puts it in Tier 3 of the naming contract.
