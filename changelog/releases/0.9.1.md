## Why Care?

JSR scored 0.9.0 at 88%. The docs it generates are the first thing people see
when they look at the package there, and an eighth of the public API had
nothing to say. Every export now has a description.

## What's New?

- **Every entry point has a module page.** `/formats`, `/formats/yang`,
  `/formats/json-schema`, `/formats/plantuml` and `/resolve-path` already
  opened with a good explanation; it just wasn't marked as the module's, so JSR
  showed those pages empty.
- **Every exported symbol is documented**: the YANG, JSON Schema and PlantUML
  result types, the image-carousel types, the link-preview, OG-fetcher and
  wikilinks plugins, and the fields on the cross-reference embed data.
- **Provenance from GitHub Actions.** Pushing a `v*` tag now publishes to JSR
  from CI, so each version links back to the commit that built it.

## How It Was Checked

`deno doc --lint` over every entry point reports no missing docs. All 310
tests pass, and `deno publish --dry-run` succeeds. No code paths changed.

## Under the Hood

- `deno doc --lint` still reports missing return types and references to
  `Plugin` and `Root` from unified and mdast. JSR's score doesn't count
  those, and fixing them means re-exporting upstream types, so they're left
  for a later pass.
- The workflow runs the same `scripts/publish-jsr.sh` as `pnpm lfm:jsr`, so
  the published README still carries the docs-v guides.
