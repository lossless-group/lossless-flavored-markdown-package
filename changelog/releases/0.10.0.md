## Why Care?

In Obsidian, `%%like this%%` is a note to yourself: visible while you edit,
gone when you read. Published through LFM, those notes went out as text, so
anything you'd written for your eyes only was on the page.

## What's New?

- **`%%…%%` comments are left out of the page**, inline or wrapping whole
  blocks: paragraphs, headings, lists, code.
- **On by default.** Pass `comments: false` to keep `%%` text as written.
- **Nothing downstream sees them.** Comments go before embeds, citations and
  heading ids run, so a commented-out heading gets no id and no
  table-of-contents entry.
- **Same rules as Obsidian:** `%%` in code is text, and an unclosed `%%`
  hides the rest of the document rather than publishing it.

## Breaking Change

Text between `%%` markers used to render. It no longer does. If a site
relied on showing it, set `comments: false`.

## How It Was Checked

All 320 tests pass, ten of them new: inline and multiple comments, a block
across a heading, list and code fence, a comment spanning paragraphs,
formatting inside a comment, `%%` in code, an unclosed comment, an emptied
list item, and `comments: false`. The docs site builds with the new guide.

## Under the Hood

- Works on the tree, not the source: one walk in document order with an
  open/closed flag, so a comment can start in one block and end in another.
- Named `remarkLfmComments`: `remark-comments` is on remark's formal list and
  does the same job with `<--COMMENTS … COMMENTS-->` markers, which puts it in
  Tier 2 of the naming contract.
