## Why Care?

Agents working in Claude or ChatGPT, and any page without a build step, had no way to render LFM: the package lived only on JSR and GitHub Packages, which the public CDNs don't serve, and its main entry imports Node's file system for the link-preview cache. Now a page can import LFM from jsDelivr and render a memo, hex-code citations numbered in first-cited order, in the browser.

## What's New?

- **`@lossless-group/lfm/browser`.** The parser, the `remarkLfm` preset and every plugin, with no Node imports. Open Graph fetching is left out (it keeps a cache file on disk); `ogFetch` is ignored with a warning. Shiki stays on `/highlight`.
- **On npm.** `pnpm lfm:npm` publishes to registry.npmjs.org, and `publish-npm.yml` does it from CI on `v*` tags, with provenance once the trusted publisher is set. jsDelivr: `https://cdn.jsdelivr.net/npm/@lossless-group/lfm@0.11.0/browser/+esm`.
- **A guide**, `docs-v/browser.md`, with a full HTML example that renders a sources list.

## How It Was Checked

All 326 tests pass. A new test bundles `/browser` for the browser with esbuild and fails on any Node builtin, and another renders two hex citations cited out of order and checks their numbering. The root and browser presets build the same tree.

## Under the Hood

- The preset's body moved to `src/preset-core.ts`, so the root and browser presets share it. The root entry's exports and output are unchanged.
- `pnpm-workspace.yaml` allows esbuild's install script, which pnpm 12 blocks by default; tsup needs esbuild.
- Known issue, logged as `context-v/issues/Preset-Transforms-Run-After-Later-Plugins.md`: chaining `.use(remarkLfm).use(remarkRehype)` in one processor runs LFM's transforms after the conversion to HTML. Render in two steps, as the guide shows.
