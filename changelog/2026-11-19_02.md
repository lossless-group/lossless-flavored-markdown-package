## Why Care?

Posts about how a team works with agents keep naming skills: "run the market-sizing skill, then the timeline one." A bare name tells the reader nothing and links nowhere. With two directives, a skill named in a sentence becomes a link with its summary on hover, and a list of skills becomes a grid of cards with a button that copies the prompt to load each one.

## What's New?

- **`:skill[slug]`** cites one skill inline.
- **`:::skill-pack`** turns a list of slugs into cards. `{title="…"}` labels the grid; `{suite="product"}` shows every skill a product rolls up, led by the product's own card. `:::agent-skills` is an alias.
- **A new guide, [Agent skills](../docs-v/agent-skills.md),** covers the syntax, the registry shape a site keeps (slug, name, summary, repo, branch, path, suite), and how to render both directives.

## How it Works

Nothing changes in the parser: LFM's preset already runs `remark-directive`, so both forms arrive as ordinary directive nodes. What LFM adds is the agreement on names and attributes, so every site that renders skills reads the same markdown. That makes this a **suggested component**: LFM standardizes the syntax, and each site keeps its own registry and draws its own cards.

The reference implementation is [FullStack VC](https://github.com/lossless-group/fullstack-vc), live on [The VC Agent Skill Pack](https://fullstack-vc.com/guides/vc-agent-skill-pack/).
